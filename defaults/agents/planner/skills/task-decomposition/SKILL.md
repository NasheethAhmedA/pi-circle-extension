# Task Decomposition

## When This Applies
Use for planning, scoping, sequencing, and turning ambiguity into an executable plan.

## Process
1. Define the goal, constraints, and success condition.
2. Split the work into meaningful steps.
3. Identify dependencies, unknowns, and decision points.
4. Order the work from unblockers to finish.
5. Return a concise actionable plan, then invoke `center`.

## Anti-Patterns
- ❌ Tasks that are too vague to execute
- ❌ No ordering or dependency logic
- ❌ Hiding uncertainty
